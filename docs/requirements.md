## 2. 项目目标与范围

### 2.1 当前必须形成的业务闭环

用户浏览模板与分类 → 查看详情和素材要求 → 选择、预览并上传图片 → 提交制作 →
Java 检查参数并创建任务，返回任务 ID → Java 后台依次执行素材检查、模拟生成、结果整理 →
前端独立跟踪多个任务 → 用户在个人记录中查看阶段、成功图片或失败原因，刷新后恢复记录及跟踪。

制作使用可控制耗时、可重复指定阶段失败的模拟生成器，不需要真实处理图片或调用 AI。
关闭或离开页面不应中断已受理的 Java 后台任务；这与服务进程重启恢复是两种不同保证。

## 4. 逐项需求与 Acceptance Criteria

下面的“给定/当/则”是可观察验收展开，来源为每节同编号正文；跨条目展开另标来源。
本轮 AC 均未执行业务验证，不预设公共 URL、HTTP 状态码、数据库字段或具体组件。

### R-01：技术栈与职责

原文定位：技术要求 / R-01，“业务执行和持久化不能仅由 Next.js 完成”。

- **AC-R-01-01**：给定交付源码，当检查依赖及入口，则前端使用 Next.js App Router、React、TypeScript，后端使用 Java、Spring Boot、MyBatis，数据库为 MySQL。
- **AC-R-01-02**：当追踪模板、素材、任务、个人记录的数据流及实际执行，则业务接口由 Java 提供，任务状态和历史可从 MySQL 读取；前端内存或 Next.js 单独执行不能替代它们。
- **AC-R-01-03**：当按 README 准备环境，则能识别兼容的框架版本、构建/启动方式；Next 直连 Java 或中间层均可，样式、状态管理和通知/执行方案有选择空间。

边界：Context 装配通过不等于真实 MySQL 连通；不以是否引入 Redis/MQ/SSE/WebSocket 作为合格条件。

### R-02：列表与模拟数据

原文定位：模板列表 / R-02，“数据通过 Java 接口获取”。

- **AC-R-02-01**：给定自造模板数据，当打开列表、切换分类并点击卡片，则可看到分类、模板标题和封面，筛选结果正确并进入对应详情；数据来自 Java。
- **AC-R-02-02**：当检查数据与演示，则能够演示不同分类及不同素材数量要求；种子文件或数据库均可，不要求 CRUD 或固定示例字段名。
- **AC-R-02-03**：当访问示例封面/素材，则有可访问的本地示例文件或合法可用资源，不依赖付费或公司内部服务；准备方式进入 README（关联 R-13）。

边界：列表不能只是前端写死；空数据、加载失败的反馈关联 R-03，资源地址失效需如实记录，不能以缺图冒充已验证。

### R-03：详情、上传与提交前校验

原文定位：模板详情与素材上传 / R-03，“不能只使用浏览器临时地址代替服务端可用的素材”。

- **AC-R-03-01**：当查看有效模板，则显示标题、描述、示例封面、素材要求和相应图片上传位；可选择、预览、替换及移除图片。
- **AC-R-03-02**：当上传进行中或失败，则界面分别给出反馈；素材未准备好或提交进行中时避免重复点击提交。
- **AC-R-03-03**：当图片数量、类型或大小不符合当前模板要求，则前端阻止不合法提交；直接向 Java 发送不合法素材或制作参数也被校验，不能依赖 UI 作为唯一边界。
- **AC-R-03-04**：给定成功准备的素材，当页面离开或 Java 后台读取输入，则素材仍为服务端可用内容；本地目录或容器数据卷可用，浏览器 blob 仅能用于本地预览。
- **AC-R-03-05**：当模板不存在、数据加载中、空数据或请求失败，则显示可理解的对应反馈，不伪装成可正常制作状态。

边界：验证数量不足/超出、类型不匹配、大小边界；具体规则来自自造模板，不把示例 5 MiB 固定到全部模板。
替换/移除时的在途上传结果需避免重新绑定到错误位置（R-03 的交互一致性展开）；不因此要求素材删除 API。

### R-04：受理与异步执行

原文定位：提交与后台处理 / R-04，“不等待全部制作结束”。

- **AC-R-04-01**：给定合法输入与可观察的较长模拟耗时，当提交，则必要参数检查及任务记录创建完成后返回任务 ID；在后台完成前可观察到受理及未完成任务。
- **AC-R-04-02**：受理后关闭/离开页面，在 Java 服务持续运行的条件下，后台继续执行；重新进入可通过记录观察结果（关联 R-09）。
- **AC-R-04-03**：连续提交多个合法任务，各自得到可区分的任务记录；串行排队和并行都可，不能要求所有任务真正同时执行。

边界：参数不合法或记录创建失败不应宣称受理成功；提交响应丢失时后台是否已创建可能未知。
前端防重复点击是必需，后端幂等和重提去重是非强制扩展，不承诺网络重提只创建一次。
不设题面未给出的毫秒级响应 SLA。

### R-05：多步骤状态与查询

原文定位：R-05，“素材检查 → 模拟生成 → 结果整理”“查询接口读取状态”。

- **AC-R-05-01**：当后台处理任务，则按上述顺序执行，每一步有独立、可观察的服务端执行边界；可用延迟与预置结果，不要求真实图片处理，不能由前端定时文案代替。
- **AC-R-05-02**：当在处理中或处理后查询任务/历史，则可读取持久化的当前阶段、整体状态以及相应结果或失败原因；整体状态至少表达等待、处理、成功、失败。
- **AC-R-05-03**：只有结果整理成功后，任务才以成功结果供查看，并记录可预览的结果地址；完成后反复查询不会变回处理中。
- **AC-R-05-04**：在没有查询请求的时段，Java 后台仍会推进；反复查询本身不推进步骤、不重新生成、不触发重执行。

边界：不固定枚举名、百分比、接口路径。失败阶段和原因关联 R-06；任务状态持久化不等于自动恢复进程中断的执行。

### R-06：失败与模拟控制

原文定位：R-06，“可重复触发指定阶段失败”“某一步失败后停止后续步骤”。

- **AC-R-06-01**：按 README 的确定性控制方式，分别指定素材检查、模拟生成、结果整理失败；重复演示时都在所选阶段失败，后续步骤没有执行。
- **AC-R-06-02**：当阶段失败，则服务端保存失败阶段与可理解原因，查询/历史和前端可显示一致信息（关联 R-05/07/09）。
- **AC-R-06-03**：按 README 调整模拟耗时后，能观察处理阶段和多任务未完成状态；同时具备可重复的正常成功路径。

边界：测试配置或开发接口均可，不要求正式页面/模板配置失败选项；不需要随机失败或用户重执行功能。
模拟配置生效范围、配置错误反馈及是否按任务固定属于待设计问题，不在这里冻结。

### R-07：状态表达与请求异常

原文定位：前端状态与历史结果 / R-07，“查询接口暂时不可用属于请求异常”。

- **AC-R-07-01**：当依次上传、提交、受理和执行，则界面区分上传中、提交请求中、任务等待/处理中、成功、失败；受理后展示任务，不继续把提交按钮当作该任务的“提交中”。
- **AC-R-07-02**：当服务端阶段或终态变化，则展示对应阶段、失败原因或成功结果；执行失败以服务端记录为依据。
- **AC-R-07-03**：已有任务信息时使查询暂时不可用，则保留已有信息，显示请求异常而不改为任务执行失败；恢复服务后有途径重新查询到真实状态。

边界：一次查询超时不能推断任务失败；不强制自动重试算法，手动恢复或合理的查询恢复均可。
上传失败、提交失败、查询失败和后台失败分别呈现，不能共用一个无语义区分的失败状态。

### R-08：多任务与查询生命周期

原文定位：R-08，“各自的状态、阶段、错误与结果互不串扰”。

- **AC-R-08-01**：连续创建多个任务并让它们具有不同阶段/结果/错误，改变或查询其中一个时，其余任务的信息不被覆盖；响应乱序仍正确关联任务。
- **AC-R-08-02**：有未完成任务时自动跟踪；某任务结束后停止对它的自动跟踪，其他未完成任务仍可更新；未完成任务集合为空时不持续轮询，包括首次进入时没有未完成任务，以及全部任务结束后的情况。
- **AC-R-08-03**：当离开相关页面或切换用户，则停止旧上下文的自动查询，清理相应的定时器、订阅等跟踪资源，并尽可能取消在途查询；旧请求的回调不得重新启动旧上下文的自动跟踪。
- **AC-R-08-04**：给定旧上下文已有查询发出，当离开页面或切换用户后，旧查询仍返回成功结果或错误，则该响应失效，不得更新当前页面上下文、新用户或其他任务的数据及请求状态；无论是否成功取消旧查询，都须满足此项。

边界：可选轮询、SSE、WebSocket 或其他合理方式，不固定库/间隔。前端停止跟踪不等于取消 Java 后台任务（R-04）。
停止跟踪是自动生命周期要求，不禁止首次加载历史记录或用户手动查看已完成记录。

### R-09：刷新恢复与结果记录

原文定位：R-09，“刷新页面后从 Java 后端恢复记录”。

- **AC-R-09-01**：用户查看个人历史时，每条记录显示创建时间、处理状态，以及成功图片或失败原因；成功图片可实际预览。
- **AC-R-09-02**：任务等待/处理中刷新页面，则从 Java 恢复记录并继续跟踪未结束任务；成功/失败记录也能恢复，不依赖页面内存。
- **AC-R-09-03**：历史数据与同一任务的查询反映服务端记录，当前阶段和原因/结果保持一致（关联 R-05）；完成记录不因刷新变回处理中。

边界：无历史需要空态；查询暂时不可用按 R-07 处理。刷新恢复是必需，服务重启自动恢复执行不要求。
不追加下载、删除、重新制作、视频、分页或排序规则。

### R-10：用户身份与个人记录

原文定位：R-10，“自行设计用户身份与个人任务记录的管理方式”。

- **AC-R-10-01**：README 说明身份如何产生、传递、保持和演示，以及个人任务如何关联该身份；能按说明得到一致的个人记录。
- **AC-R-10-02**：以可区分身份 A、B 演示：各自创建任务后看到对应个人历史；刷新保留相应记录；切换身份时旧请求不能将 A 的记录写入 B 的视图（R-08/09/10 的联合验收展开）。

边界：个人记录的范围需由 Java 查询/用例维护，不能只靠前端隐藏全部用户数据（R-01/09 的职责展开）。
题面未规定生产级认证强度、账号体系、身份存续方式、模板是否共享或素材访问策略；这些需在设计时说明假设，
不能从“个人记录”扩展出注册、密码、OAuth、角色/租户服务等必做功能。

### R-11：参考界面与交互

原文定位：视觉与基本可用性 / R-11，“截图中的题外功能不扩展正文要求”。

- **AC-R-11-01**：列表、详情/制作、历史结果具有清晰布局、信息层级、间距和状态反馈；参考已提供图的主要布局，无图区域自行设计。
- **AC-R-11-02**：桌面主要流程可操作，小屏也能完成主要操作；不要求额外移动端设计或指定断点/像素尺寸。
- **AC-R-11-03**：按钮、输入、对话框（若使用）具有合适语义，键盘焦点可见且可用，上传及图标按钮有可理解标签。

已观察参考图：列表有分类导航及封面卡片网格；详情/制作图为素材与操作区搭配 History 卡片，
包含处理中及失败提示。UI-01～UI-03 是正文列举的附件名称，不据此声称已取得三个独立附件文件。
图中的积分、会员、语言切换、视频标签、删除图标等不新增正文外需求；品牌、文案、图片可替换，不做逐像素验收。

### R-12：CI 与关键测试

原文定位：工程与交付 / R-12，“重点覆盖后端步骤顺序与失败中断”。

- **AC-R-12-01**：源码包含 push 或 pull request 自动触发的 GitHub Actions，检查前端 lint、TypeScript、构建及 Java 测试/构建；其他托管平台可有等价流水线，压缩包保留配置。
- **AC-R-12-02**：实际测试能验证后端三步骤顺序、指定阶段失败时后续不执行，而不只验证应用启动。
- **AC-R-12-03**：实际前端测试覆盖多任务互不串扰，以及查询异常与任务执行失败的区分；不是仅检查静态文本或镜像实现的断言。

边界：不限定框架、覆盖率、数量，不要求 E2E 或自动部署；CI 配置存在与远程执行成功分别记录。
R-08 的清理/乱序、R-09 的恢复可在相关行为测试或人工验收中验证，不另加题面没有规定的测试工具门槛。

### R-13：提交材料与说明

原文定位：R-13 及“试卷说明”；材料和 README 清单均为强制说明范围。

- **AC-R-13-01**：交付可读取源码仓库、本地完整项目或源码包，包含前后端完整源码、依赖版本/锁文件、数据库结构与初始化数据、CI 和 README；仓库方式注明验收 commit，压缩包可排除缓存/依赖目录。
- **AC-R-13-02**：README 包含技术版本、结构、构建/测试/启动命令、前后端与数据库连接、配置项及脱敏示例、数据库初始化和模拟数据/素材准备。
- **AC-R-13-03**：README 说明主要接口及请求响应字段、任务状态/阶段/后台执行方式，给出成功、指定阶段失败、耗时调整、多任务、刷新恢复和身份/个人记录的演示方法。
- **AC-R-13-04**：README 如实列出完成/未完成、已知限制、实际投入（含开发、验证和整理）、未实现重启恢复等边界，以及部署和回滚基本步骤；不要求真实生产操作或复杂发布平台。
- **AC-R-13-05**：README 如实说明是否使用 AI；使用时描述任务拆解、上下文、生成/修改、验证和修正工作流，可举具体例子，无须私人聊天、账号或全部提示词；复用脚手架/开源代码/素材时说明来源及主要范围。
- **AC-R-13-06**：最终提交按收到任务的沟通渠道和双方约定日期交付；澄清也使用该渠道。

边界：网页倒计时不自动替代双方约定日期；不虚构投入时长、完成度、AI 验证记录或来源授权。

### R-14：推荐的容器交付

原文定位：R-14，“最好提供”“如未提供 Compose”。

- **AC-R-14-01（推荐）**：若交付 Compose，按说明准备必要配置后，`docker compose up --build`（或已说明的等价命令）可启动前端、Java、MySQL 并具备初始化数据；包含所需 Dockerfile、脱敏配置样例和说明。
- **AC-R-14-02（未选 Compose 时的要求）**：提供必要的启动、配置和初始化说明，供源码审查及容器运行准备；不以缺少 Compose 直接认定遗漏强制业务功能。
- **AC-R-14-03（验收证据规则）**：Compose 解析、镜像构建、服务就绪、初始化和实际业务运行分别记录结果；不要求公网地址或真实部署截图。

验收方式正文说明：评估者先审源码、入口、依赖脚本和材料；需要运行时，安装、构建、测试与应用执行均在容器隔离环境，
不直接运行于评估者宿主机。无 Compose 时招聘方决定仅审源码或另备容器。
这不要求本轮运行应用，也不能把开发者历史本机检查伪称为评估者容器验收。

## 5. 核心业务流程与失败边界

### 5.1 主流程及前后端分工

| 步骤 | 用户/前端行为 | Java 与持久化行为 | 可观察结果 / 来源 |
| --- | --- | --- | --- |
| 1. 取得身份上下文 | 按选定身份方案进入；查看自己的记录 | 识别用例上下文、按约定管理个人任务范围 | 身份方式可解释、可演示；R-10 |
| 2. 浏览模板 | 加载、筛选分类、打开详情 | 从种子/数据库读取模板，提供 Java 接口与可访问示例资源 | 分类/卡片/详情匹配；R-02 |
| 3. 准备素材 | 按模板上传位选择、预览、替换/移除；展示上传反馈 | 校验接收到的素材，保存为后台可用内容；校验制作参数 | 数量/类型/大小符合模板；R-03 |
| 4. 提交与受理 | 准备未完或提交中避免重复点击；受理后转入任务视图 | 完成必要校验并创建任务记录，返回 ID；之后后台执行 | 请求不等待完整制作；R-04、R-07 |
| 5. 后台处理 | 可继续浏览或创建其他任务，前端不负责推进任务 | 顺序执行素材检查、模拟生成、结果整理，保存阶段和状态 | 三个独立执行边界；R-05 |
| 6. 独立跟踪 | 自动更新每个未完成任务，按 ID 关联响应与错误 | 查询读取服务端记录，无查询仍继续执行 | 不串扰、不以查询驱动；R-05、R-08 |
| 7. 终态与结果 | 成功预览图片，失败显示阶段/原因；终态停止自动跟踪 | 整理成功记录结果地址；阶段失败停止后续并保存原因 | 个人历史可查；R-05、R-06、R-09 |
| 8. 刷新/重新进入 | 从 Java 恢复记录；继续跟踪未完成任务 | 返回持久化历史与当前任务信息 | 内存重置不丢记录；R-09 |

步骤 1 是身份上下文的逻辑前提，不要求额外登录页面。模板是否公开、上传与身份如何关联仍待设计。
采用轮询还是推送不改变上述责任；前端离开时释放跟踪资源，Java 任务继续。

### 5.2 替代流程、边界与保障等级

| 情形 | 当前要求 / 验收展开 | 不由此引入的功能或待设计内容 | 来源 |
| --- | --- | --- | --- |
| 加载中、空列表、模板不存在、请求失败 | 清晰反馈，不展示成可正常制作的数据 | 页面布局、错误码、恢复按钮形式待设计 | R-03、R-11 |
| 图片数量/类型/大小不符 | 前端校验，Java 同样验证输入；不将不合法输入当作正常受理 | 文件规则具体值由模板决定；真实图像解析策略待设计 | R-03、R-04 |
| 上传失败、替换/移除时旧上传返回 | 上传反馈准确，提交只引用准备好的当前素材；旧结果不覆盖新选择 | 不追加素材删除、断点上传、自动重试 | R-03 的交互展开 |
| 提交失败或响应丢失 | 区分提交请求状态与后台任务状态；不能凭断网宣布任务执行失败 | 是否查询已受理任务、如何提示可能重复提交待设计；后端幂等非强制 | R-04、R-07；范围排除正文 |
| 三个阶段任一指定失败 | 确定性触发，记录阶段/原因，后续不执行 | 不要求随机失败或重执行 | R-05、R-06 |
| 查询超时/不可用，后台可能已结束 | 保留已知任务信息，提供恢复查询途径；以恢复后的服务端状态为准 | 不要求固定自动重试、退避或即时一致性 SLA | R-07 |
| 多任务响应乱序，某任务先结束 | 信息按任务隔离，终态任务停止跟踪，其余继续 | 不要求真正并行后台执行 | R-04、R-08 |
| 页面离开/关闭、身份切换 | 清理订阅/请求，旧响应不得污染新上下文；受理任务继续后台执行 | 不等于取消任务，不新增取消 API | R-04、R-08 |
| 页面刷新 | 从 Java 恢复个人历史并跟踪未完成任务 | 不能只用 localStorage 或前端缓存代替后端持久记录 | R-01、R-09 |
| Java 进程重启或提交后派发前崩溃 | 如实说明未实现的自动恢复及派发窗口，不能承诺自动续跑 | 自动恢复/Outbox/MQ 非当前必做；已保存记录仍需持久化，不能把不恢复解释为允许丢历史 | R-01、R-13；范围排除正文 |
| 已完成任务被再次查询或旧更新到达 | 查询不推进，完成不退回处理中；实现时需保护状态一致性 | 乐观锁/条件更新属于待设计工程选择 | R-05、R-06；SRC-ARCH |
| 结果地址无法访问 | 成功结果可预览是验收要求；不可访问时不能记为该验收点通过 | 不要求云存储或下载服务；文件/数据库不一致处理待设计 | R-05、R-09 |

输入合法性检查与后台“素材检查”是不同执行边界：受理前做必要校验，后台仍须保留第一个独立步骤，
并支持在该步骤确定性模拟失败。不能为演示后台失败而撤掉服务端输入校验（R-03～R-06）。

## 6. DDD 候选概念、职责与业务不变量

### 6.1 候选建模深度

以下为需求分析建议，命名不是已确定的类或公共契约；保持现有候选包边界，
不提前建立新领域、Java 类、表、接口或枚举。是否为独立限界上下文还需后续验证。

| 候选概念 | 候选模型角色 | 业务理由与来源 | 不应提前引入 |
| --- | --- | --- | --- |
| 制作任务 / ProductionTask | `domain.task` 的 Aggregate Root 候选 | 有独立身份、生命周期、阶段、结果/失败与终态一致性；R-04～R-06 | 不受约束 setter、重试/取消状态、通用工作流引擎 |
| 模板与素材要求 | `domain.template` 的只读模型/查询投影；素材要求可为 Value Object | 分类、详情和输入约束；R-02/03；没有模板修改用例时不强造聚合 | 模板 CRUD、版本仓库、发布审批 |
| 已上传素材 | `domain.asset` 的 Entity 候选；是否需聚合待一致性分析 | 服务端可用素材需可引用且满足模板要求；R-03/04 | 固定素材寿命、去重策略、对象存储模型 |
| 任务状态、当前阶段、失败信息、结果引用、调用者标识 | Value Object 候选；精确字段待设计 | 需要表达一致且可解释的业务含义；R-05～R-10 | 供应商 DTO、文件绝对路径、认证框架类型 |
| 阶段执行信息 | 先考虑任务内部值；确有独立身份/审计需求再考虑 Entity | 三步边界须可观察，但原文不要求独立步骤记录表；R-05/06 | 完整执行日志、执行尝试聚合、事件溯源 |
| 个人历史 | 查询投影，用例返回个人任务记录 | 持久化任务的读取视图；R-09/10 | 与任务重复存储的历史聚合、独立读库/CQRS |
| 生成结果 | 先考虑任务的结果引用与可预览资源 | 仅要求成功图片预览；R-05/09 | 独立 Result 领域、分享/作品集生命周期 |
| 跨对象业务规则 | Domain Service 仅在单对象无法自然承担时考虑 | 例如任务输入与模板素材规则的比较；R-03/04 | 为每个模型机械创建 Service，跨域访问内部 Repository |
| 创建、执行、查询、恢复记录等用例 | Application Service，即项目 Cases | 编排公开领域能力、归属检查、事务与派发；R-03～R-10；SRC-ARCH | Controller 直接访问 DAO；将执行器或事务放进聚合 |

### 6.2 当前已确定的规则与候选不变量

这些规则来自当前题面；后续由聚合、Case、查询和前端分别承担，不能全部塞进任务聚合。

| 规则标识 | 必须维持的业务语义 | 来源 | 候选责任边界 |
| --- | --- | --- | --- |
| INV-01 | 被受理的制作参数及素材满足所选模板约束；未准备完成不能作为正常提交 | R-03、R-04 | 素材/模板规则与创建 Case；前端亦反馈 |
| INV-02 | 素材检查先于模拟生成，模拟生成先于结果整理；每步真实存在执行边界 | R-05 | task 生命周期规则 + 执行 Case 编排 |
| INV-03 | 任一步失败后不执行后续阶段；失败信息包含可理解原因及所处阶段 | R-06 | task 状态一致性 + 执行 Case |
| INV-04 | 成功意味着结果整理已成功且记录可预览地址，不能仅因模拟生成返回就成功 | R-05、R-09 | task 完成规则 + 结果资源适配 |
| INV-05 | 完成后的查询不让任务退回处理中；失败不能被后续步骤继续推进 | R-05、R-06 | task 状态规则；持久化并发保护为工程设计 |
| INV-06 | 查询读取服务端状态，不是执行推进器；无查询时后台仍能运行 | R-04、R-05 | Case 及适配器职责隔离 |
| INV-07 | 一个任务的状态、阶段、错误与结果只属于该任务，不能污染另一任务 | R-08 | task 标识和前端任务状态关联 |
| INV-08 | 请求查询失败不改变后台任务执行结论；已有任务信息保留 | R-07 | 前端请求状态与任务状态分离 |
| INV-09 | 个人记录对应当前身份；身份切换后旧请求不能写入新身份视图 | R-08～R-10 的联合展开 | 个人查询 Case + 前端请求上下文 |
| INV-10 | 刷新恢复读取 Java/MySQL 的任务记录，未完成任务重新跟踪；终态停止自动跟踪 | R-01、R-08、R-09 | 持久化查询 + 前端生命周期 |

状态的需求语义为等待 → 处理中 → 成功/失败；处理过程具有素材检查、模拟生成、结果整理三个顺序阶段。
这不是具体枚举、字段组合或迁移图的最终设计。失败可以发生在任一阶段，当前不要求离开终态重执行。
阶段与整体状态分别表达有利于解释当前需求，是否分字段以及允许组合应在后续建模明确。

### 7.2 既有工程决策及前后端职责

SRC-ENG/SRC-ARCH 已选择 Java 17、Boot 4.0.x、MyBatis Starter 4.0.x、MySQL 8.4 LTS、
Next.js 16 App Router、strict TypeScript、Node.js 22 和 npm lockfile；精确版本以配置为准。
这是项目在 R-01 版本选择空间内的已有决策，不是题面要求这些精确版本。

- **前端**：交互与预览、上传/提交请求反馈、按任务独立展示、查询异常、自动跟踪及清理、刷新恢复、可用性；不推进业务阶段或伪造服务端终态。
- **Trigger/API**：传输校验、调用者提取和 DTO 转换，调用 Case；错误契约和身份方式待设计。
- **Cases**：编排创建/执行/查询、资源归属、事务及派发，跨域使用公开能力；不直接依赖别域内部 DAO/PO 或具体基础设施。
- **Domain**：维护真实业务规则与合法状态变化；简单模板/历史读取保持轻量；不依赖 Spring/MyBatis/HTTP。
- **Infrastructure**：MyBatis/MySQL、素材存储、Mock 与执行机制；不通过查询推进任务，不在生成适配器内直接更新业务表。

生成、素材存储、派发的候选 Port 分别遵循现有 `domain.task.adapter.port`、
`domain.asset.adapter.port`、`cases.task.port` 规划；只在实际用例需要时定义最小契约。
提交后派发、独立短事务、长时间模拟等待不占数据库事务、并发/旧更新保护来自既有工程原则。
本轮不选择锁实现、线程池、Spring Event、迁移工具或新增框架。
