# UI 布局调整与本地验证

日期：2026-10-31（Asia/Shanghai）。范围：ASMT-R-11，既有 IP-12 / IP-14 页面展示层。
本轮按用户提供的四张截图参考布局，保留原来的浅色背景、深绿色操作色和现有业务契约。
不将截图中的会员、积分、视频、删除、计费或改密功能加入当前范围。

## 布局约定

| 页面 | 布局与主要操作 | 参考依据 |
| --- | --- | --- |
| `/`、`/templates` | 紧凑品牌/账号顶栏，横向分类，竖向封面网格；点击模板开始创作 | 图 1 的分类和封面卡片结构；首页直接进入目录 |
| `/templates/[templateId]` | 桌面左侧预览/要求/上传/提交，右侧本人任务卡片；小屏按相同顺序上下排列 | 图 2、3 的窄创作区与宽 History 工作区 |
| `/history` | 独立任务卡片网格，显示真实状态、时间、阶段、失败原因或成功图片 | 图 2、3 的状态卡片；保留现有查询恢复入口 |
| 账户信息 | 原生模态框，头像/显示名、用户名/账户标识、记录入口 | 图 4 的分组结构；仅展示已有 AccountView 字段 |

目标视口：1440×1000、390×844。保持原有加载、空数据、请求异常、部分数据可用、成功和未登录反馈。
模板目录仍由 Java 数据驱动，当前只有两个模板，不为填满布局增加假模板。
上传替换/移除、提交同步 gate、未知提交结果核对、身份切换清理、每任务轮询与 Blob 生命周期保持原实现。
账户框使用原生 dialog，支持键盘打开、Esc 关闭及焦点返回；身份 epoch 变化时卸载旧账户框。

## 验证结果

- `frontend/`：Node 22.21.1，`npm ci`、`npm run lint`、`npm run typecheck`、`npm run build` 通过。
- `frontend/`：`npm run test:ci`，14 个文件、246 项测试通过，包含新增账户框身份失效行为与首页目录入口测试。
  测试环境缺少原生 dialog 方法，组件测试显式模拟 open/close；焦点与 Esc 行为另外在 Chrome 检查。
- 根目录：`docker compose --env-file .env.example config --quiet` 通过；不代表容器启动或业务验收。
- 本地隔离 Chrome + Playwright，在两个目标视口检查真实 Next 页面渲染：分类筛选、上传及提交、三种任务状态、
  成功图片、空记录、未登录、历史请求恢复、分类失败下的可用模板、目录失败/恢复、加载和封面失败反馈。
- 检查桌面左右栏、手机上下排列与横向溢出；账户框键盘打开、Esc、关闭后焦点返回；
  工具栏控件至少 44px 高，主要文字配色对比度达到 4.5:1，关闭动画偏好下仍显示状态。
- 浏览器使用拦截的测试 API 响应和项目打包 JPEG；这验证展示与交互，不代表真实 Java/MySQL 或完整容器验收。
  后端代码未修改，本轮未重跑 Maven。

截图、浏览器检查记录和技能证据 JSON 在本地忽略目录 `frontend/test-results/ui-redesign/`；
该目录的脚本副本 `verify-ui-layout.mjs` 使用本机 bundled Playwright/Chrome 路径，仅用于本地复核。
本轮不覆盖 `docs/tasks.md` 中既有人工验收、真实后端或完整容器的待办状态。
